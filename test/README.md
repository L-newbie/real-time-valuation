## 一、判定标准

**功能跑得通、不报错、有结果 = 通过。**

| 判定项 | 通过 | 不通过 |
|---|---|---|
| 模块能加载 | import 不抛错 | 语法错误、引用断裂、循环依赖 |
| 函数能执行 | 调用不抛异常 | TypeError / not a function |
| 有返回值 | 返回预期类型且非空 | **NaN / undefined / null** |
| 状态有变化 | 加了基金列表确实多一条 | 调了但 state 没变 |
| 页面能渲染 | 挂载无报错 | 白屏、挂载抛错 |
| 数据能落盘 | 写了再读能读回 | 读回来是空（用户数据丢失） |
| 交互有反应 | 点了/滑了状态变了 | 没反应、状态机卡死 |

**不判**：数值精确性、性能快慢、UI 样式美观、代码写法。

## 二、用例组织：编号 + 分步流程

每个功能一条**编号用例**，内部按**准备 → 执行 → 验证 → 清理**逐步走，
任何一步断了就报出**卡在第几步**：

```
CASE-04-16 · 仪表盘数据聚合
  步骤1  准备：装载 3 笔测试持仓        ✔
  步骤2  执行：getDashboardStats()      ✔
  步骤3  验证：返回字段齐全              ✔
  步骤4  验证：今日盈亏为有效数字        ✘  ← 卡在这
          └ 实得 NaN（界面会显示 --）
```

用例之间**完全独立**：每条用例前自动重置 store、清空存储、复位时钟与网络。

## 四、测试环境（全部离线）

**测试绝不访问真实接口**，不消耗密钥额度，不发真实邮件。

| 替身 | 作用 |
|---|---|
| 内存 Storage | 替代 localStorage；支持故障模式（模拟隐私模式/配额超限） |
| 固定时钟 | 冻结在 2026-08-07（周五）14:30 北京时间；支持任意穿越（跨日/漏日回放） |
| 网络桩 | 拦截 `fetch` 与 `<script>` 注入（JSONP）；三模式：**正常 / 接口失败 / 脏数据** |
| Worker 桩 | 同线程假实现；支持静默模式（验证看门狗超时兜底） |
| matchMedia 桩 | 三档断点切换（移动/平板/桌面） |
| Canvas 桩 | happy-dom 无 Canvas，补最小实现供图表初始化 |
| 手势合成 | 构造 touch/mouse 事件序列：滑动、长按、双击、拖拽、粘贴 |

> ⚠️ 关键点：`vitest.config.ts` 里关掉了 happy-dom 的资源加载
> （`disableJavaScriptFileLoading` 等），否则 JSONP 注入的 `<script src>`
> 会被 happy-dom 真的去请求，导致 ECONNRESET 且测试依赖外网。

## 六、命令

```bash
npm run test              # 提交前跑这个：功能测试 + 接口探活，一次跑完
npm run test:watch        # 开发时
npm run test:smoke        # 只跑接口探活
SKIP_SMOKE=1 npm run test # 跳过探活，只跑功能测试
npm run precommit         # vue-tsc 类型检查 + 上述全部
```

`npm run test` 由 `test/run.mjs` 依次拉起两个子进程，输出分两段：

| | ① 功能可用性检查 | ② 外部接口探活 |
|---|---|---|
| 数据 | 桩数据（离线） | **真实请求** |
| 用时 | ~18 秒 | ~10-60 秒（视网络） |
| 是否影响退出码 | ✅ **是，唯一的通过条件** | ❌ **否，永远不影响** |
| 进 CI | ❌ 否 | ❌ 否 |
| 防的是 | 代码被改坏 | 上游接口变了（仅告知） |

### 测试不进 CI

`.github/workflows/deploy.yml` 只做 `pnpm install → pnpm run build → 部署`，**不执行测试**。

本套测试的定位是**开发者本地自测工具**：提交代码前跑一次，确认没把功能改坏。
需要强制拦截时，可自行在本地挂 git pre-commit 钩子：

```bash
# .git/hooks/pre-commit
SKIP_SMOKE=1 npm run test || exit 1
```

**为什么用两个子进程而不是合成一次运行**：主测试装了网络桩拦截所有 `fetch`（保证离线可跑、
结果稳定），探活则必须真发请求——两者环境要求互斥，同进程内无法共存。分进程也便于
单独吞掉探活的退出码。

### 探活未连通的可能原因

报告会自动归因并给出解释，不需要你猜：

| 现象 | 报告提示 |
|---|---|
| **全部 24 个不通** | 判定为本机网络限制（无外网出口 / 需配代理 / VPN 防火墙），属预期，无需处理 |
| 部分超时 | 接口响应慢或被墙，跨境接口（Yahoo、RSS）常见 |
| HTTP 429/403 | 被限流或封禁，短时间请求过多，稍后再试 |
| DNS 解析失败 | 本机网络受限，与代码无关 |
| 连接被拒绝/中断 | 代理不稳定或服务临时故障 |

**这些都不影响提交。** 探活是体检报告不是红绿灯——公共接口和免费代理本就会抖，
设成门槛会导致网络一抖就红，很快就没人看了。

## 七、禁改保护

- **`CLAUDE.md`** —— AI 会话开始时自动读取，用户无感。写明禁改清单与"测试失败改业务代码"规则。

禁改范围：
1. 图像识别功能（`src/modules/ai/**`、`use-image-recognition.ts`）
2. 问题反馈功能（`feedback.vue`、`src/modules/feedback/**`、`email-service.ts`）
3. 配置密钥（`src/config/constants.ts` 整文件）
4. 测试流程（`test/**`、`CLAUDE.md`、`.claude/**`）

hook 已实测验证：拦住 Edit/Write 禁改文件、`sed -i`、重定向覆写、`rm`；
放行正常业务代码编辑、`npm test`、`git status`、以及对禁改文件的**读取**。

## 八、维护须知

- **新增功能时**：在对应 suite 加用例，并上调 `00-07` 的用例数基线
- **`00-07` 基线只能上调，不能下调** —— 下调等于放行删除测试
- 网络样本在 `setup/net-stub.ts` 里，接口结构变化时更新样本即可
- 用例失败时先看报告给出的**步骤号 + 现象**，再定位业务代码
